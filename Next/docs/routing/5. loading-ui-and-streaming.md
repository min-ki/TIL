# Loading UI and Streaming

> The special file loading.js helps you create meaningful Loading UI with React Suspense.

특별한 파일인 loading.js는 React Suspense를 사용해 의미 있는 Loading UI를 만들 수 있도록 도와준다.

> With this convention, you can show an instant loading state from the server while the content of a route segment loads.

이 컨벤션을 사용해, 라우트 세그먼트의 내용이 로드될 때 서버에서 로딩 상태를 보여줄 수 있다.

> The new content is automatically swapped in once rendering is complete.

렌더링이 완료되면 새로운 컨텐츠가 자동으로 교체된다.

<img src="https://nextjs.org/_next/image?url=%2Fdocs%2Flight%2Floading-ui.png&w=1920&q=75">

## Instant Loading States

> An instant loading state is fallback UI that is shown immediately upon navigation.

인스턴트 로딩 상태는 네비게이션 시 즉시 표시되는 대체 UI이다.

> You can pre-render loading indicators such as skeletons and spinners, or a small but meaningful part of future screens such as a cover photo, title, etc.

스켈레톤과 스피너와 같은 로딩 인디케이터나 커버 사진, 제목 등의 그려질 화면의 작지만 의미 있는 부분을 미리 렌더링할 수 있다.

> This helps users understand the app is responding and provides a better user experience.

이는 사용자가 앱이 응답하고 있음을 이해하고 더 나은 사용자 경험을 제공한다.

> Create a loading state by adding a loading.js file inside a folder.

폴더 내부에 loading.js 파일을 추가하여 로딩 상태를 만들 수 있다.

<img src="https://nextjs.org/_next/image?url=%2Fdocs%2Flight%2Floading-special-file.png&w=1920&q=75">

```tsx
// app/dashboard/loading.tsx
export default function Loading() {
  return <LoadingSkeleton />;
}
```

> In the same folder, loading.js will be nested inside layout.js. It will automatically wrap the page.js file and any children below in a <Suspense> boundary.

같은 폴더 내에서, loading.js는 layout.js 내부에 중첩됩니다. 이는 자동으로 page.js 파일과 아래의 모든 자식을 <Suspense> 경계로 래핑합니다.

<img src="https://nextjs.org/_next/image?url=%2Fdocs%2Flight%2Floading-overview.png&w=1920&q=75">

Good to know:

> Navigation is immediate, even with server-centric routing.

네비게이션은 server centric routing과 함께 즉시 이루어진다.

> Navigation is interruptible, meaning changing routes does not need to wait for the content of the route to fully load before navigating to another route.

네비게이션은 중단 가능하며, 다른 라우트로 네비게이션하기 전에 라우트의 내용이 완전히 로드될 필요가 없다.

> Shared layouts remain interactive while new route segments load.

공유된 레이아웃은 새로운 라우트 세그먼트가 로드될 때까지 상호작용이 유지된다.

> Recommendation: Use the loading.js convention for route segments (layouts and pages) as Next.js optimizes this functionality.

추천: Next.js는 이 기능을 최적화하기 때문에 라우트 세그먼트(레이아웃과 페이지)에 대해 loading.js 컨벤션을 사용하십시오.

## [Streaming with Suspense](https://nextjs.org/docs/app/building-your-application/routing/loading-ui-and-streaming#streaming-with-suspense)

> In addition to loading.js, you can also manually create Suspense Boundaries for your own UI components. The App Router supports streaming with Suspense for both Node.js and Edge runtimes.

loading.js 외에도 직접 UI 컴포넌트를 위한 Suspense 경계를 만들 수 있다. App Router는 Node.js와 Edge 런타임 모두에서 Suspense를 사용한 스트리밍을 지원한다.

Good to know:

Some browsers buffer a streaming response. You may not see the streamed response until the exceeds 1024 bytes. This typically only affects “hello world” applications, but not real applications.

일부 브라우저는 스트리밍 응답을 버퍼링한다. 1024바이트를 초과할 때까지 스트리밍 응답을 볼 수 없을 수 있다. 이는 일반적으로 "hello world" 애플리케이션에만 영향을 미치며, 실제 애플리케이션에는 영향을 미치지 않는다.

### What is Streaming?

> To learn how Streaming works in React and Next.js, it's helpful to understand Server-Side Rendering (SSR) and its limitations.

React와 Next.js에서 스트리밍이 작동하는 방법을 이해하려면 서버 사이드 렌더링(SSR)과 그 한계를 이해하는 것이 도움이 된다.

> With SSR, there's a series of steps that need to be completed before a user can see and interact with a page:

SSR에서 사용자가 페이지를 볼 수 있고 상호작용할 수 있기 전에 완료해야 할 일련의 단계가 있다.

> 1. First, all data for a given page is fetched on the server.

먼저, 주어진 페이지를 위한 모든 데이터를 서버에서 가져온다.

> 2. The server then renders the HTML for the page.

서버는 1번 후에 페이지의 HTML을 렌더링한다.

> 3. The HTML, CSS, and JavaScript for the page are sent to the client.

페이지의 HTML, CSS, JavaScript이 클라이언트로 전송된다.

> 4. A non-interactive user interface is shown using the generated HTML, and CSS.

생성된 HTML과 CSS를 사용하여 비 인터렉티브한 사용자 인터페이스가 표시된다.

> 5. Finally, React hydrates the user interface to make it interactive.

마지막으로, 리액트는 사용자 인터페이스가 상호작용할 수 있도록 하이드레이트한다.

<img src="https://nextjs.org/_next/image?url=%2Fdocs%2Flight%2Fserver-rendering-without-streaming-chart.png&w=3840&q=75">

> These steps are sequential and blocking, meaning the server can only render the HTML for a page once all the data has been fetched.

이러한 단계들은 순차적이고 블로킹되며, 서버는 모든 데이터를 가져온 후에만 페이지의 HTML을 렌더링할 수 있다.

> And, on the client, React can only hydrate the UI once the code for all components in the page has been downloaded.

그리고, 클라이언트에서는 페이지의 모든 컴포넌트 코드가 다운로드된 후에만 리액트가 UI를 하이드레이트할 수 있다.

> SSR with React and Next.js helps improve the perceived loading performance by showing a non-interactive page to the user as soon as possible.

React와 Next.js의 SSR은 사용자에게 가능한 빨리 비인터랙티브 페이지를 보여줌으로써 인지된 로딩 성능을 향상시킨다.

<img src="https://nextjs.org/_next/image?url=%2Fdocs%2Flight%2Fserver-rendering-without-streaming.png&w=3840&q=75">

> However, it can still be slow as all data fetching on server needs to be completed before the page can be shown to the user.

그러나, 페이지를 사용자에게 보여주기 전에 서버에서 모든 데이터를 가져와야 하기 때문에 여전히 느릴 수 있다.

> Streaming allows you to break down the page's HTML into smaller chunks and progressively send those chunks from the server to the client.

스트리밍을 사용하면 페이지의 HTML을 작은 청크로 분할하고 서버에서 클라이언트로 청크를 점진적으로 전송할 수 있다.

<img src="https://nextjs.org/_next/image?url=%2Fdocs%2Flight%2Fserver-rendering-with-streaming.png&w=3840&q=75">

> This enables parts of the page to be displayed sooner, without waiting for all the data to load before any UI can be rendered.

이를 통해 페이지의 일부를 더 빨리 표시할 수 있으며, UI를 렌더링하기 전에 모든 데이터를 기다릴 필요가 없다.

> Streaming works well with React's component model because each component can be considered a chunk.

스트리밍은 각 컴포넌트를 청크로 간주할 수 있기 때문에 React의 컴포넌트 모델과 잘 작동한다.

> Components that have higher priority (e.g. product information) or that don't rely on data can be sent first (e.g. layout), and React can start hydration earlier.

우선순위가 높은 컴포넌트(예: 제품 정보) 또는 데이터에 의존하지 않는 컴포넌트(예: 레이아웃)를 먼저 보낼 수 있으며, 리액트는 하이드레이션을 더 빨리 시작할 수 있다.

> Components that have lower priority (e.g. reviews, related products) can be sent in the same server request after their data has been fetched.

우선순위가 낮은 컴포넌트(예: 리뷰, 관련 제품)는 데이터를 가져온 후 동일한 서버 요청에서 보낼 수 있다.

<img src="https://nextjs.org/_next/image?url=%2Fdocs%2Flight%2Fserver-rendering-with-streaming-chart.png&w=3840&q=75">

> Streaming is particularly beneficial when you want to prevent long data requests from blocking the page from rendering as it can reduce the Time To First Byte (TTFB) and First Contentful Paint (FCP).

스트리밍은 페이지 렌더링을 차단하는 긴 데이터 요청을 방지하고 Time To First Byte (TTFB)와 First Contentful Paint (FCP)를 줄일 때 특히 유용하다.

> It also helps improve Time to Interactive (TTI), especially on slower devices.

특히 느린 기기에서 Time to Interactive (TTI)를 개선하는 데 도움이 된다.

### Example

> <Suspense> works by wrapping a component that performs an asynchronous action (e.g. fetch data), showing fallback UI (e.g. skeleton, spinner) while it's happening, and then swapping in your component once the action completes.

<Suspense>는 비동기 작업(예: 데이터 가져오기)을 수행하는 컴포넌트를 래핑하고, 작업이 진행되는 동안 대체 UI(예: 스켈레톤, 스피너)를 표시한 다음, 작업이 완료되면 컴포넌트를 교체함으로써 작동한다.

```tsx
import { Suspense } from "react";
import { PostFeed, Weather } from "./Components";

export default function Posts() {
  return (
    <section>
      <Suspense fallback={<p>Loading feed...</p>}>
        <PostFeed />
      </Suspense>
      <Suspense fallback={<p>Loading weather...</p>}>
        <Weather />
      </Suspense>
    </section>
  );
}
```

> By using Suspense, you get the benefits of:

Suspense를 사용하면 다음과 같은 이점을 얻을 수 있다.

> 1. Streaming Server Rendering - Progressively rendering HTML from the server to the client.

스트리밍 서버 렌더링 - 서버에서 클라이언트로 HTML을 점진적으로 렌더링한다.

> 2. Selective Hydration - React prioritizes what components to make interactive first based on user interaction.

선택적 하이드레이션 - 사용자 상호작용에 따라 리액트가 먼저 상호작용할 컴포넌트를 우선순위로 둔다.

For more Suspense examples and use cases, please see the React Documentation.

### SEO

> Next.js will wait for data fetching inside generateMetadata to complete before streaming UI to the client. This guarantees the first part of a streamed response includes <head> tags.

Next.js는 generateMetadata 내부의 데이터 가져오기가 완료될 때까지 클라이언트로 UI를 스트리밍하기 전에 기다립니다. 이는 스트리밍된 응답의 첫 부분이 <head> 태그를 포함하도록 보장합니다. (SEO를 위해 첫 스트리밍에 메타데이터를 포함할 수 있도록 기다린다.)

> Since streaming is server-rendered, it does not impact SEO. You can use the Rich Results Test tool from Google to see how your page appears to Google's web crawlers and view the serialized HTML (source).

스트리밍은 서버에서 렌더링되기 때문에 SEO에 영향을 미치지 않는다. 구글의 Rich Results Test 도구를 사용하여 페이지가 구글의 웹 크롤러에게 어떻게 보이는지 확인하고 직렬화된 HTML을 볼 수 있다.

### Status Codes

> When streaming, a 200 status code will be returned to signal that the request was successful.

스트리밍할 때, 요청이 성공했음을 나타내기 위해 200 상태 코드가 반환된다.

> The server can still communicate errors or issues to the client within the streamed content itself, for example, when using redirect or notFound.

서버는 리다이렉트나 notFound를 사용할 때와 같이 스트리밍된 내용 자체에서 클라이언트에게 오류나 문제를 전달할 수 있다.

> Since the response headers have already been sent to the client, the status code of the response cannot be updated. This does not affect SEO.

응답 헤더가 이미 클라이언트로 전송되었기 때문에 응답의 상태 코드를 업데이트할 수 없다. 이는 SEO에 영향을 미치지 않는다.
