## 항목 13: 엔티티의 플루언트 API 스타일 적용 방법

> 플루언트 스타일은 주로 읽기 쉽고 코드의 자연스러운 흐름을 표현하도록 설계된다.

### 엔티티 세터를 통한 플루언트 스타일

```java
@Entity
public class Author {
  @Id
  @GeneratedValue(strategy = GenerationType.IDENTITY)
  private Long id;

  private String name;
  private String genre;
  private int age;

  @OneToMany(cascade = CascadeType.ALL, mappedBy = "author", orphanRemoval = true)
  private List<Book> books = new ArrayList<>();

  public Author addBook(Book book) {
      this.books.add(book);
      book.setAuthor(this);
      return this;
  }

  public Author removeBook(Book book) {
      book.setAuthor(null);
      this.books.remove(book);
      return this;
  }

  public Author setId(Long id) {
      this.id = id;
      return this;
  }

  public Author setName(String name) {
      this.name = name;
      return this;
  }

  public Author setGenre(String genre) {
      this.genre = genre;
      return this;
  }

  public Author setAge(int age) {
      this.age = age;
      return this;
  }

  public Author setBooks(List<Book> books) {
      this.books = books;
      return this;
  }
}
```

Setter들이 void 대신 this를 반환하기 때문에 플루언트 스타일로 서로 연결(chain)해 사용

```java
Author author = new Author()
    .setName("John Doe")
    .setGenre("Fiction")
    .setAge(45)
    .addBook(new Book().setTitle("Book1"))
    .addBook(new Book().setTitle("Book2"));
```

## 항목 14: 하이버네이트 프록시를 통한 자식 측에서 부모 연관관계 채우기

스프링 내장 메서드
- findById() -> EntityManager#find() 를 사용하여 엔티티를 반환
- getOne() -> EntityManager#getReference() 를 사용하여 프록시 객체를 반환

1. findById()
- 영속성 콘텍스트 -> 2차 캐시 -> 데이터베이스 순으로 엔티티를 찾음

2. getOne()

findById와는 다르게 하이버네이트 프록시(proxy) 객체를 반환

### findById() 사용

```java
@Transactional
public void addBookToAuthor() {
    Author author = authorRepository.findById(1L).orElseThrow();

    Book book = new Book();
    book.setIsbn("001-MJ");
    book.setTitle("Spring Boot JPA Best Practices");
    book.setAuthor(author);

    bookRepository.save(book);
}
```

위 구문 쿼리
```sql
select
    author0_.id as id1_0_0_,
    author0_.age as age2_0_0_,
    author0_.genre as genre3_0_0_,
    author0_.name as name4_0_0_,
from
    author author0_
where
    author0_.id=?

-- insert book
insert into book (author_id, isbn, title) values (?, ?, ?)
```

### getOne() 사용

```java
@Transactional
public void addBookToAuthor() {
    Author proxy = authorRepository.getOne(1L);

    Book book = new Book();
    book.setIsbn("001-MJ");
    book.setTitle("Spring Boot JPA Best Practices");
    book.setAuthor(author);

    bookRepository.save(book);
}
```

하이버네이트는 초기화되지 않는 프록시의 외래키 값을 설정할 수 있기 때문에
이 코드는 하나의 INSERT문만 실행한다.

위 구문 쿼리
```sql
-- insert book
insert into book (author_id, isbn, title) values (?, ?, ?)
```

> 확실히 findById()를 사용하는 것보다 낫다.

## 항목 15: 영속성 레이어에서 자바 8 Optional 사용 방법

이번 항목 목표: 영속성 레이어에서 자바 8 Optional API 사용을 위한 모범 사례를 알아보는 것

**자바 8 Optional의 목적**
> Optional은 '결과 없음'을 나타내는 명확한 방법이 필요한 라이브러리 메서드 반환 타입에 사용되는 제한된 메커니즘 제공을 위한 것이며,
> null을 대신 사용하면 오류 발생 가능성이 압도적으로 높다.


### 엔터티에서의 Optional 사용

Optional은 엔터티의 특정 게터(getter - null반환 가능성이 있는 게터)에서 사용할 수 있다.

```java
@Entity
public class Author implements Serializable {
    // ...

    public Optional<String> getName() {
        return Optional.ofNullable(name);
    }

    public Optional<String> getGenre() {
        return Optional.ofNullable(genre);
    }

    // ...
}

public class Book implements Serializable {
    // ...

    public Optional<String> getTitle() {
        return Optional.ofNullable(title);
    }

    public Optional<String> getIsbn() {
        return Optional.ofNullable(isbn);
    }

    public Optional<Author> getAuthor() {
        return Optional.ofNullable(author);
    }

    // ...
}
```

다음과 같은 경우는 Optional을 사용하지 말아야 한다.

- 엔터티 필드 (Optional은 Serializable되지 않는다.)
- 생성자 및 setter 인자
- 기본 타입 및 컬렉션을 반환하는 게터
- 기본키에 관련된 게터

### Repository에서 Optional 사용

Optional을 사용해 쿼리의 결과 세트를 감쌀 수 있다.

`Optional<Author> author = authorRepository.findById(1L);`

```java
@Repository
@Transactional(readOnly = true)
public interface AuthorRepository extends JpaRepository<Author, Long> {
    Optional<Author> findByName(String name);
}

@Repository
@Transactional(readOnly = true)
public interface BookRepository extends JpaRepository<Book, Long> {
    Optional<Book> findByTitle(String title);
}
```

쿼리 빌더 메커니즘뿐만아니라 JPQL과 네이티브 쿼리에서도 잘 동작한다.

```java
@Query("SELECT a FROM Author a WHERE a.name = ?1")
Optional<Author> fetchByName(String name);

@Query("SELECT a.genre FROM Author a WHERE a.name = ?1")
Optional<String> fetchGenreByName(String name);

@Query(value = "SELECT genre FROM author WHERE name = ?1", nativeQuery = true)
Optional<String> fetchGenreByNameNative(String name);
```

## 항목 16: 불변 엔터티 작성 방법
https://github.com/AcornPublishing/spring-boot-jpa/tree/main/spring-boot-persistence-main/chapter2/ImmutableEntity

**불변 엔티티**

- `@Immutable(org.hibernate.annotations.Immutable)` 어노테이션 지정 필요
- 어떤 종류의 연관관계도 포함되면 안된다.
- hibernate.cache.use_reference_entries 설정이 true로 지정돼야 한다.

> 불변 엔티티는 분해된 상태가 아닌 엔티티 참조로 2차 캐시에 저장된다. 이렇게 되면 분해된 상태에서 엔티티를 재구성하는 성능 저하를 방지할 수 있다.

분해된 상태는 하이드레이티드(hydrated) 상태라고도 하는데, 엔티티가 하나의 객체 형태가 아닌 개별 속성을 따로 갖는 상태를 말한다.

## 항목 17: 엔티티 복제 방법

https://github.com/AcornPublishing/spring-boot-jpa/tree/main/spring-boot-persistence-main/chapter2/CloneEntity

```java
@Entity
public class Author implements Serializable {
    private static final long serialVersionUID = 1L;

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private String genre;
    private int age;

    @ManyToMany(/* ... */)
    private Set<Book> books = new HashSet<>();

    // private 생성자
    private Author() {
    }

    // 복제 생성자
    public Author(Author author, boolean cloneChildren) {
        this.genre = author.getGenre(); // 장르만 복사한다.

        // 연관도서 복사
        books.addAll(author.getBooks());
    }
}

@Transactional
public void cloneAuthor() {
    Author author = authorRepository.fetchByName("Mark Janel");
    Author authorClone = new Author(author); // 복제 생성자 호출

    authorClone.setAge(54);
    authorClone.setName("Farell Tliop");
    authorRepository.save(authorClone);
}

```

## 항목 18: 더티 트래킹을 활성화하는 이유와 방법

> 더티 체킹 (Dirty Checking)은 현재 영속성 컨텍스트에 로드된 이후 수정된 관리 중(managed)인 엔티티를 플러시 시점에
> 감지하는 하이버네이트 메커니즘. 애플리케이션을 대신해 적절한 SQL UPDATE 문을 생성하고 실행한다.
> 하이버네이트는 관리중인 엔티티의 속성이 하나만 변경된 경우에도 모든 관리 엔티티를 스캔한다.

하이버네이트 5 이전의 더티 체킹 메커니즘은 자바 Reflection API에 의존
- 성능 관점에서 엔티티 수가 적다면 무해하지만 많은 수의 관리 엔티티가 있다면 성능 저하가 발생할 수 있다.

하이버네이터 5부터 더티 체킹 메커니즘은 속성의 변경 사항을 추적하는 엔티티의 기능인 더티 트래킹 메커니즘에 의존
- 이 메커니즘이 작동하려면 하이버네이트 Bytecode Enhancement 프로세스가 애플리케이션에 추가돼야 하며, 플러그 설정 해야한다.

```xml
<plugin>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-maven-plugin</artifactId>
</plugin>
<plugin>
    <groupId>org.hibernate.orm.tooling</groupId>
    <artifactId>hibernate-enhance-maven-plugin</artifactId>
    <version>${hibernate.version}</version>
    <executions>
        <execution>
            <configuration>
                <failOnError>true</failOnError>
                <enableDirtyTracking>true</enableDirtyTracking>
            </configuration>
            <goals>
                <goal>enhance</goal>
            </goals>
        </execution>
    </executions>
</plugin>
```

더티 트래킹 활성화 여부는 디컴파일하고 다음과 같은 코드를 검색해야 한다.
```java
@Transient
private transient DirtyTracker $$_hibernate_tracker;
```

https://vladmihalcea.com/how-to-enable-bytecode-enhancement-dirty-checking-in-hibernate/

하이버네이트 Bytecode Enhancement는 다음과 같은 3가지 주요 메커니즘 제공
- 더티 트래킹
- 속성 지연 초기화
- 연관관계 관리 (양방향 연관관계에서의 자동 동기화)

## 항목 19: 불리언을 Yes/No로 매핑하는 방법

```SQL
CREATE TABLE author (
    id bigint(20) NOT NULL AUTO_INCREMENT,
    age int(11) NOT NULL,
    best_selling varchar(3) NOT NULL,
    genre varchar(255) DEFAULT NULL,
    name varchar(255) DEFAULT NULL,
    PRIMARY KEY (id)
)

```

위와 같은 테이블에서 best_selling 칼럼을 불리언 값으로 매핑한다고 가정

```java
@Entity
public class Author {
    // ...
    @NotNull
    private Boolean bestSelling; // 여기서 불린으로 선언

    public Boolean isBestSelling() {
        return bestSelling;
    }

    public void setBestSelling(Boolean bestSelling) {
        this.bestSelling = bestSelling;
    }
}
```

위와 같이 선언하면 하이버네이트는 다음과 같이 매핑 시도

| 자바 타입 | 하이버네이트타입 | JDBC 타입 |
|---|---|---|
| boolean/Boolean | BooleanType | BIT |
| boolean/Boolean | NumericBooleanType | INTEGER(0 또는 1) |
| boolean/Boolean | YesNoType | CHAR (N/n 또는 Y/n) |
| boolean/Boolean | TrueFalseType | CHAR (F/f 또는 T/t) |

예시에서는 위의 어느것도 해당하지 않음.

하이버네이트가 모든 CRUD 처리에 적용할 커스텀 변환기 (converter)를 작성하는 것
- AttributeConverter 인터페이스를 구현한다.

```java
@Converter(autoApply = true) // Boolean을 사용하는 모든 속성에 적용된다.
public class BooleanConverter implements AttributeConverter<Boolean, String> {
    @Override
    public String convertToDatabaseColumn(Boolean attr) {
        return attr == null ? "No" : "Yes";
    }

    @Override
    public Boolean convertToEntityAttribute(String dbData) {
        return !"No".equals(dbData);
    }
}
```

특정 속성에만 적용하려면 autoApply 속성을 false로 설정하고 @Convert 어노테이션을 사용한다.

```java
@Entity
public class Author {
    // ...
    @Convert(converter = BooleanConverter.class)
    private Boolean bestSelling;
}
```

> `@Enumerated` 이 달린 속성에는 AttributeConverter를 적용할 수 없다.
