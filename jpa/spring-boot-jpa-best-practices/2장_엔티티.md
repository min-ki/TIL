# 엔티티

## 항목 13: 엔티티의 플루언트 API 스타일 적용 방법

> 플루언트 스타일은 주로 읽기 쉽고 코드의 자연스러운 흐름을 표현하도록 설계된다.

### 엔티티 세터를 통한 플루언트 스타일

```java
@Entity
public class Author {
  @Id
  @GeneratedValue(strategy = GenerationType.IDENTITY)
  private Long id;

  private String name;
  private String genre;
  private int age;

  @OneToMany(cascade = CascadeType.ALL, mappedBy = "author", orphanRemoval = true)
  private List<Book> books = new ArrayList<>();

  public Author addBook(Book book) {
      this.books.add(book);
      book.setAuthor(this);
      return this;
  }

  public Author removeBook(Book book) {
      book.setAuthor(null);
      this.books.remove(book);
      return this;
  }

  public Author setId(Long id) {
      this.id = id;
      return this;
  }

  public Author setName(String name) {
      this.name = name;
      return this;
  }

  public Author setGenre(String genre) {
      this.genre = genre;
      return this;
  }

  public Author setAge(int age) {
      this.age = age;
      return this;
  }

  public Author setBooks(List<Book> books) {
      this.books = books;
      return this;
  }
}
```

Setter들이 void 대신 this를 반환하기 때문에 플루언트 스타일로 서로 연결(chain)해 사용

```java
Author author = new Author()
    .setName("John Doe")
    .setGenre("Fiction")
    .setAge(45)
    .addBook(new Book().setTitle("Book1"))
    .addBook(new Book().setTitle("Book2"));
```

## 항목 14: 하이버네이트 프록시를 통한 자식 측에서 부모 연관관계 채우기

스프링 내장 메서드
- findById() -> EntityManager#find() 를 사용하여 엔티티를 반환
- getOne() -> EntityManager#getReference() 를 사용하여 프록시 객체를 반환

1. findById()
- 영속성 콘텍스트 -> 2차 캐시 -> 데이터베이스 순으로 엔티티를 찾음

2. getOne()

findById와는 다르게 하이버네이트 프록시(proxy) 객체를 반환

### findById() 사용

```java
@Transactional
public void addBookToAuthor() {
    Author author = authorRepository.findById(1L).orElseThrow();

    Book book = new Book();
    book.setIsbn("001-MJ");
    book.setTitle("Spring Boot JPA Best Practices");
    book.setAuthor(author);

    bookRepository.save(book);
}
```

위 구문 쿼리
```sql
select
    author0_.id as id1_0_0_,
    author0_.age as age2_0_0_,
    author0_.genre as genre3_0_0_,
    author0_.name as name4_0_0_,
from
    author author0_
where
    author0_.id=?

-- insert book
insert into book (author_id, isbn, title) values (?, ?, ?)
```

### getOne() 사용

```java
@Transactional
public void addBookToAuthor() {
    Author proxy = authorRepository.getOne(1L);

    Book book = new Book();
    book.setIsbn("001-MJ");
    book.setTitle("Spring Boot JPA Best Practices");
    book.setAuthor(author);

    bookRepository.save(book);
}
```

하이버네이트는 초기화되지 않는 프록시의 외래키 값을 설정할 수 있기 때문에
이 코드는 하나의 INSERT문만 실행한다.

위 구문 쿼리
```sql
-- insert book
insert into book (author_id, isbn, title) values (?, ?, ?)
```

> 확실히 findById()를 사용하는 것보다 낫다.

## 항목 15: 영속성 레이어에서 자바 8 Optional 사용 방법

이번 항목 목표: 영속성 레이어에서 자바 8 Optional API 사용을 위한 모범 사례를 알아보는 것

**자바 8 Optional의 목적**
> Optional은 '결과 없음'을 나타내는 명확한 방법이 필요한 라이브러리 메서드 반환 타입에 사용되는 제한된 메커니즘 제공을 위한 것이며,
> null을 대신 사용하면 오류 발생 가능성이 압도적으로 높다.


### 엔터티에서의 Optional 사용

Optional은 엔터티의 특정 게터(getter - null반환 가능성이 있는 게터)에서 사용할 수 있다.

```java
@Entity
public class Author implements Serializable {
    // ...

    public Optional<String> getName() {
        return Optional.ofNullable(name);
    }

    public Optional<String> getGenre() {
        return Optional.ofNullable(genre);
    }

    // ...
}

public class Book implements Serializable {
    // ...

    public Optional<String> getTitle() {
        return Optional.ofNullable(title);
    }

    public Optional<String> getIsbn() {
        return Optional.ofNullable(isbn);
    }

    public Optional<Author> getAuthor() {
        return Optional.ofNullable(author);
    }

    // ...
}
```

다음과 같은 경우는 Optional을 사용하지 말아야 한다.

- 엔터티 필드 (Optional은 Serializable되지 않는다.)
- 생성자 및 setter 인자
- 기본 타입 및 컬렉션을 반환하는 게터
- 기본키에 관련된 게터

### Repository에서 Optional 사용

Optional을 사용해 쿼리의 결과 세트를 감쌀 수 있다.

`Optional<Author> author = authorRepository.findById(1L);`

```java
@Repository
@Transactional(readOnly = true)
public interface AuthorRepository extends JpaRepository<Author, Long> {
    Optional<Author> findByName(String name);
}

@Repository
@Transactional(readOnly = true)
public interface BookRepository extends JpaRepository<Book, Long> {
    Optional<Book> findByTitle(String title);
}
```

쿼리 빌더 메커니즘뿐만아니라 JPQL과 네이티브 쿼리에서도 잘 동작한다.

```java
@Query("SELECT a FROM Author a WHERE a.name = ?1")
Optional<Author> fetchByName(String name);

@Query("SELECT a.genre FROM Author a WHERE a.name = ?1")
Optional<String> fetchGenreByName(String name);

@Query(value = "SELECT genre FROM author WHERE name = ?1", nativeQuery = true)
Optional<String> fetchGenreByNameNative(String name);
```
